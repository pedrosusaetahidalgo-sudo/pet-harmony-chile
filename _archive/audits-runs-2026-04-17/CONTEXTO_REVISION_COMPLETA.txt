1. RESUMEN EJECUTIVO
================================================================================

Paw Friend es una plataforma chilena de gestion integral de mascotas con
directorio veterinario verificado. Combina funcionalidades de salud animal
(ficha clinica PDF, recordatorios, vacunas), social (feed, comunidad), y
gamificacion (Paw Cards coleccionables estilo TCG, misiones, niveles).

La "joya de la corona" es la ficha medica PDF descargable + directorio publico
de veterinarios filtrable por comuna y especialidad.

Stack: React 18 + TypeScript 5.8 + Vite 5 + Supabase (Postgres + Auth + Storage
+ Edge Functions Deno) + Capacitor 7 (Android/iOS). Pagos via Flow.cl (pasarela
chilena). IA via Claude API (Anthropic).

Actualmente en "pivot medico": la app es 100% gratis para duenos de mascotas
(USER_PREMIUM=false). El modelo de monetizacion activo es B2B (planes para
veterinarios y clinicas).

Estado al 2026-04-15:
- TypeScript: 0 errores (npx tsc -b)
- Build: PASA
- Bundle principal: ~334 kB / 100 kB gzip (index chunk)
- Git: limpio, sincronizado con origin/main

- Edge Functions: 26 activas + _shared/ (6 helpers)

10. SISTEMA DE ROLES Y EXPERIENCIAS
================================================================================

10.1 ROLES DISPONIBLES

| Rol        | Determinacion                        | Experiencia UI                    |
|------------|--------------------------------------|-----------------------------------|
| owner      | Cualquier usuario autenticado (default) | Entretenida: gamificacion, Paw Cards, feed, colores vivos |
| provider   | Registro en service_providers        | Profesional: dashboard clinico, tema teal medico, sin gamificacion |
| admin      | Registro en admin_access (is_active) | Panel interno: metricas, moderacion, sistema |

10.2 DUAL-ROLE SWITCHING (useActiveRole)

- Hook: useActiveRole() en src/hooks/useActiveRole.tsx
- Context: { role, isProvider, isProviderLoading, toggle, setRole }
- Detecta si es provider via query a service_providers (TanStack Query)
- Persiste en localStorage key: pf_active_role
- Toggle visible en Header como pill segmentado "Dueno" / "Profesional"
- Al cambiar a owner → redirect a /home + toast
- Al cambiar a provider → redirect a /provider/dashboard + toast
- Si isProvider=false y role queda en 'provider', fuerza reset a 'owner'

10.3 GUARDS DE RUTA

- RoleGuard: enforza requiredRole ('owner' | 'provider')
  - provider requerido + no es provider → redirect a fallback (/home) + toast
  - provider requerido + en modo owner → auto-switch a provider
  - owner requerido + en modo provider → auto-switch a owner
  - Shows null while loading (previene flash-redirect)

- AdminRoute: verifica admin_access con is_active=true
- ProtectedRoute: verifica sesion autenticada

10.4 SEPARACION DE EXPERIENCIAS

- Provider views (/provider/*): tema profesional teal, sin Paw Cards/misiones/badges
- Owner views: gradientes, animaciones holo, gamificacion, colores brand purple
- Sin leakage: menus/sidebar/bottom tabs solo muestran rutas del rol activo
- Rutas owner-only: /paw-game, /paw-collection, /misiones (RoleGuard owner)
- Rutas provider-only: /provider/* (RoleGuard provider)

10.5 FLUJO MASCOTA HUERFANA (vet crea mascota sin cuenta de dueno)

1. Vet crea mascota via NewPatientForm → pet con pending_owner_email, owner_id=null
2. Edge function send-pet-invitation envia email con token via Resend API
3. Dueno click link → useClaimPetInvitation reclama la mascota
4. Re-claim si pierde email: useAutoClaimByEmail auto-detecta por email verificado
5. Re-claim manual: boton "Tengo un codigo de mi vet" en /my-pets (ClaimPetDialog)
6. Admin monitorea en Admin > Usuarios > Mascotas pendientes (AdminPendingPets)
